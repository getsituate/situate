# Checking and activating plugins

Use check_plugin_changes({changes:[{pluginId}],checks:[{pluginId,script,fixtures?,responses?,processes?,timeoutMs?}]}). Publish only intended packages; include new dependencies with their consumers until active. Check targets and affected existing consumers even when those consumers are not being published. Follow needsChecks with focused checks. Omit revision for current prepared code; select an older revision only after an explicit restore request, checking against current dependencies. After all required checks pass, use activate_plugin_changes({checkId}). needsRecheck requires adapting/rechecking, never silently rolling back dependencies.

## Functional scripts and previews

Checks run selected async JavaScript in a supervised Worker, not a frontend closure. Script locals are plugin={tools,skills,skill(path),invokeTool(name,args),invokeExport(name,args)}, host (the invocation-bound SDK), preview={open,step,close}, and assert={ok,equal}. There is no check.* wrapper. Use await plugin.invokeTool(name,args) or await plugin.invokeExport(name,args), then assert.equal(actual,expected) or assert.ok(value) against independent expected behavior. plugin.skills contains frozen captured {path,text} descriptors; plugin.skill(path) returns captured skill text and rejects unknown paths. Skills-only checks assert actual captured text through plugin.skill, not a copied literal. At least one successful assertion is required; a failed assertion fails the entire check even if caught. Use await preview.open({viewId:"sample:main"}), await preview.step({action:"read"}) for text, await preview.step({action:"click",selector}), await preview.step({action:"fill",selector,value}), await preview.step({action:"capture"}) for a {captured:true,mimeType:"image/png"} receipt, and await preview.close(). host.preview has the same methods. These calls await the UI responder, not asynchronous service work started by mounting or event handlers. Poll for the expected visible state with a bounded deadline before asserting or reading saved data; never repeat a potentially writing action just to wait. Native code retains captured PNGs and attaches them to the tool result separately; image bytes are not returned to the script. Service/script timeout terminates the Worker and drains native operations; Vue preview rendering retains its hang/restart limitation.

Failed script results retain the successful assertions count and, for a comparison failure, failure={assertion,operator,actual,expected}. assertion is the one-based assertion index; actual/expected are bounded value previews. The first failed assertion remains decisive even if caught. Unknown exceptions use plugins.checkFailed, not an unavailable-runtime diagnosis; type/reference/syntax failures have distinct codes. Raw exception messages are omitted: do not throw debug payloads to inspect values. Results include the last 32 host-operation observations without credential values, file contents, HTTP bodies or process streams; observationsTruncated identifies omitted earlier operations. assertionsKnown:false means a terminated or otherwise failed execution did not supply a counter. Check results remain in this conversation; no separate report file is created. When macOS shell access is available, operational JSONL logs are normally at ~/Library/Logs/com.getsituate.app/diagnostics/segment-*.jsonl; use Python or jq to filter by workspace_id, context.trace_id and timestamp. Development app paths can differ. These logs are metadata, not assertion reports. Keep all test inputs and compared values synthetic.

fixtures may supply files/config/data/credentials maps of flat paths/names to synthetic strings. responses maps exact 'METHOD URL' to {status,body}; unmatched requests fail without real network. processes is at most 128 exact {executable,args?,exitCode,stdout,stderr} fixtures; omitted args means [], unmatched processes never spawn. Attach fixtures to the checks item for the dependency that performs the operation, not merely its consumer. Include meaningful errors and consumer behavior, not just import success. Fixtures/scripts are temporary and never activated. Recovery permits checks and checked activation while unrelated installed plugins remain paused.

## Activation outcomes

Only activate an exact passed checkId. Relevant edits or dependency changes require fresh checks. Activation waits for affected running actions rather than aborting or replaying them. No further activation confirmation or mandatory post-activation agent check is required. activated:true with followUpError means activation already happened; report it and do not repeat activation. An unknown outcome is not proof that nothing happened. Inspect actual active revisions before recovery. Keep code activation distinct from missing permissions/accounts and live-access verification. Closing a view does not stop work; workspace closure/quit does. Interrupted work waits for user input.
