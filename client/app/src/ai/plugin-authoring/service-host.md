# Service host APIs

Within a service invocation, context.files/config/data.read(path) returns {text,revision}; write(path,text,expectedRevision) uses null only for creation. Stale writes require a fresh read and reconsideration, not blind retries. config/data are plugin-scoped stores. context.credentials.get/set/remove uses device-local credentials; never embed secrets in code, screenshots or fixtures.

Prefer context.files.list(query?), search({...query,text}) and readMany(paths) over process execution for workspace content. query has optional roots (workspace-relative directories, default whole workspace) and extensions (case-insensitive). list/search return sorted [{path,changeToken}] without symlinks or technical paths. Search is a nonempty case-sensitive literal substring of UTF-8 text; binary files are skipped. Missing roots and exceeded limits fail without silent truncation. readMany returns [{path,text,revision}] in input order or fails as a whole: at most 256 files, 1 MiB per file and 16 MiB total. Batches are not atomic workspace snapshots. changeToken is metadata invalidation, not a content revision or identity. config/data do not have list/search/watch.

context.network.request({url,method?,headers?,body?}) returns {status,body}. UI interactions use admitted service calls rather than direct browser network or durable storage operations.

Within a [Library original-reading invocation](../document-sources/reference.md#library-profile-version-2), `context.documents.fromFile(path)` reads an absolute regular-file path using desktop permissions. It is available to path-backed workspaces with local process access; reject paths outside the source's agreed folder before invoking it. `context.documents.fromHttp({url,headers?})` performs a GET without redirects and returns `{status,original?}`. Only HTTP 200 yields an original; a different status returns without a handle. Both operations can return `{error}` with `unsupported`, `permission`, `not-found`, `unavailable`, `cancelled` or `too-large`. Originals are limited to 32 MiB and a single successful handle per invocation. HTTP check fixtures encode the body as base64; checks don't access live URLs or the local folder.

context.process.capability() reports availability, platform, interpreter/dialect/args, limits and ownership. Check it before offering native execution. context.process.run({executable,args?,timeoutMs?}) invokes an absolute executable (an .exe on Windows) with literal arguments, default []; scripts require an explicit interpreter. macOS uses POSIX sh; Windows reports Windows PowerShell and its arguments. Commands run in the workspace but are not sandboxed and can access outside files and the network. Use the reported ownership and containment fields; neither platform can stop work delegated to independent services. Initialization has no process capability. No installs, secret injection, permission setup or account setup are automatic.

Process replies contain isError, commandResult:{Ok:{outcome,exitCode,signal,stdout,stderr}}|{Err:ShellError}, beforeHistoryRevision, afterHistoryRevision, reconciliationError and attribution. outcome is exited/cancelled/timedOut; exitCode/signal may be null. Streams contain text,capturedBytes,totalBytes,truncated,incomplete; discarded bytes cannot be recovered. Check isError, exitCode and reconciliationError. Null revisions and uncertainExternalChangesMayCoexist do not attribute every change to the command. Timeout is at most 300000 ms; argv at most 256 entries and 65536 UTF-8 bytes total; Windows also limits the quoted command line to 32767 UTF-16 units including its terminator. No cwd or environment overrides. Synthetic fixtures cannot prove installed programs, external script contents, permissions, accounts or live access.
