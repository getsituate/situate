# Loading feedback

Show what is being opened, in the place where it will appear. Keep anything that is already useful on screen. Mini Bend gives a wait a recognizable, quiet expression: eyes move, the arch stays still. Frequent actions should feel responsive, not like a welcome sequence.

## Choose the placement

| Situation                                                                               | Treatment                                                                                                                                                                                                | Keep available                                                                                                                           |
| --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| One list, section or result area is waiting                                             | **Inline.** A 16 px Mini Bend beside a short status, aligned where the first result would appear. Use one cue for the list, not one per row.                                                             | Section heading, surrounding navigation and independent actions.                                                                         |
| A pane has no usable content yet                                                        | **Centered.** A 32 px Mini Bend above a status, centered in the affected content area. Use the same composition inside a document preview even if the preview is only part of a pane.                    | Known title, tab, pane history and sibling panes. For a document, preserve selection, metadata and the way back to results.              |
| An entire workspace layout is not ready                                                 | **Workspace composition.** Use the centered status and Mini Bend with a static paper-and-tabs motif. Reserve this for the workspace handoff, not each pane, tab switch, refresh or app launch animation. | Workspace selection or exit whenever available; keep the workspace navigation if it is already usable.                                   |
| Existing content remains valid while updating                                           | **Retain content.** Use no visible indicator for a quiet refresh. For a user-requested update that takes time, put a compact status next to its trigger or result heading.                               | Scroll, focus and usable results for the same selection. Never show the previous workspace or conversation as if it were the new target. |
| A button submits something, a transfer has measurable progress, or the agent is working | Use the button's busy state, `SituateProgress` with a real value, or the existing chat activity feedback, respectively.                                                                                  | The relevant action context. These states do not become loading screens.                                                                 |

If the layout of the result is known and space needs reserving, a static placeholder can preserve that space. Do not add shimmer, fake message bubbles or placeholder list items merely to occupy a surface. For frequent list operations, a stable label is enough if the miniature mark would compete with real content.

## When to show it

1. Enter the pending state as soon as the request starts. Show the known destination immediately. Until the first result resolves, do not show an empty message, a new-chat greeting or an actionable placeholder. For a large target, reserve its content area immediately even if the cue has not appeared yet.
2. As a starting point, show the cue only if that same operation is still pending after **200 ms**. The delay avoids a flash on fast reads and does not delay fetching, input or results. Keep it in the presentation layer, keyed to the current request. Use immediate acknowledgement at the trigger when the user's action would otherwise look ignored. Review the threshold with native timing and repeated use; it is not a performance target.
3. End immediately on success, confirmed empty result, failure, cancellation or navigation away. Do not hold for a blink, an exit animation or a minimum display time. Reuse one cue across consecutive phases of one task: reading file bytes, decoding and rendering the first page are all part of opening the preview. A late result must not restore an old cue or replace a newer target.
4. If a surface never became usable, use the standard error screen with supported recovery and a way out. If only an action in a usable view failed, use the standard error dialog and keep the prior content. Do not convert an unresolved error into an empty result or let a retry hide needed recovery controls.

Use a localized verb and object, such as “Opening conversation…” or “Loading conversations…”. Keep the label steady and independent of the animation. Announce it politely once from a stable live region outside the `aria-busy` subtree; mark the affected region, not the whole view. Hide decoration from assistive technology. Do not move focus to the cue. Honor reduced motion with the same text and a still mark; suspend the eye frames offscreen, in a hidden window or behind a modal. The workspace illustration has no motion of its own.

## Client placement map

This map covers user-visible waits in the Vue client. Async imports, background services and writes only need a new loading surface if they withhold a visible result the user is waiting for.

| Client surface                                                                                                                               | Previous feedback                                                                                                                                 | Recommended placement                                                                                                                                                                                                      |
| -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| App launch, workspace selection and layout restore (`App.vue`, `WorkspaceEntry`, `AppShell`, `OnboardingHost`)                               | Startup status, action-level busy states and a text-only layout wait; separate recovery paths.                                                    | Workspace composition only when opening or restoring the workspace content. Keep selection actions local and first-run welcome separate.                                                                                   |
| Saved conversation and pane navigation (`ViewHost`, `layout/runtime.ts`, `ChatPane`, `ai/chat.ts`)                                           | Host status for availability or a lazy view; chat greeting follows absence of history, which does not establish that the transcript has loaded.   | One centered cue from target selection to the first usable snapshot; do not swap from a generic loader to another loader. Preserve the tab title and history.                                                              |
| Active and archived conversations (`AppShell`, `AppSidebar`, `ai/chat.ts`)                                                                   | Shared flag covers both list loading and conversation creation. The empty message is suppressed while busy, but no loading label replaces it.     | One inline cue for first list load, with archive and empty states only after results are known. Preserve usable rows during refresh. Creation remains feedback on **New conversation**.                                    |
| Files and attached changes (`FileEditor`, `ChatBatchChanges`)                                                                                | Text for tree, editor body, revisions, deleted items and file changes in chat.                                                                    | Center in the initial editor body; use inline at the tree, history or change list. Retain the surrounding editor or chat.                                                                                                  |
| Documents (`document-store`, `DocumentsView`, `DocumentReading`)                                                                             | Library results have a text state; preview combines byte reads, PDF rendering or image decoding, a 200 ms reveal threshold and a 16 px Mini Bend. | Inline in library results; centered in the empty preview, as one wait through the first render. On later page or zoom changes keep the last usable rendering when the renderer permits; use local feedback only if needed. |
| Models, connections and settings (`AiSetup`, `AiSettings`, `AiConnections`, `ChatModelPicker`, `SettingsView`, `AppearanceSettings`)         | Text, busy flags and lazily mounted settings panels; model refresh already has its own status.                                                    | Inline at the first unavailable section or picker. Retain existing choices during refresh where safe. Center only if the entire selected settings pane has no usable content.                                              |
| Plugin inventory and development (`PluginManagement`, `PluginCodeBrowser`, `AssignmentChanges`) and license notices (`LicenseNoticesAccess`) | Text-only wait in the affected list, file area, changes view or notices dialog.                                                                   | Inline for subsections and dialog bodies; centered for an entire unavailable pane. Keep action failures separate.                                                                                                          |
| Older chat messages, embedded images and background refreshes                                                                                | Incremental or lazy work inside already displayed content.                                                                                        | Keep the transcript and scroll anchor. If a wait becomes noticeable, show feedback at the history boundary or media, not in the whole chat.                                                                                |
| App updates, dictation model downloads, saves, imports and chat execution                                                                    | Action-specific busy, progress or activity status.                                                                                                | Keep their own semantics and placement. Opening a conversation does not mean the assistant is working.                                                                                                                     |
