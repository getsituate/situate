# Discovery questions

Read the relevant product context, requirements and supplied references before asking questions. Reuse answers already available; identify conflicts rather than silently choosing a source.

Clarify only what changes the next design decision:

- Who is doing what, in which situation and on which device?
- What is difficult today, and what outcome would be better?
- Which decision is open, and which constraints are already approved?
- What evidence or artifact would help resolve it?

Ask a few focused questions about the largest uncertainty. Offer concrete choices when useful, without restricting answers to them. Wait when the answer would change scope or direction; proceed with explicit provisional assumptions for minor reversible choices.

Do not require a brand questionnaire, variant count or visual preferences before exploring a workflow. Ask about fidelity and visual references only when they affect the requested artifact.

Return a short brief: scenario, desired outcome, constraints with sources, open decision and next exploration. Use `clarify-goals-and-user-problems` if the underlying problem remains unclear. A design request is not evidence of general user demand.
