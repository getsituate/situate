# Wireframe

Start with a scenario and an open structural decision. Read relevant requirements and use `discovery-questions` if either is missing.

Draw only the screens and transitions needed to examine that decision. Use neutral styling, simple components and readable labels. Include plausible synthetic task, note or document content; avoid filler text that hides information-density and naming problems.

Show:

- How the user enters and recognizes the current context.
- The main action, supporting information and navigation.
- Completion, backtracking and the most important failure or interruption.
- Where chat, direct manipulation or an approval step is proposed.

Use `generate-variations` when comparing approaches. Do not force three alternatives for a settled or narrow decision. Place alternatives together when that makes comparison easier.

Annotate consequential choices and unresolved behavior beside the relevant screen, outside product copy. Link each option to the question it addresses. Distinguish proposed behavior from existing requirements.

Review the sequence against the task and applicable keyboard, touch and accessibility needs. Stop at sufficient fidelity to decide structure. Report the recommendation and uncertainty rather than polishing a disposable sketch. Record a selected direction only when the user makes that decision; a selection does not establish a new product requirement.
